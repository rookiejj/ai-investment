⚠️ **수동 전용 / 테스트·정합성 점검용 명령 — 자동 트리거 금지**

`/update`의 변형. 정상 운영에는 영향 없음. 사용자가 슬래시 명령으로 직접 호출했을 때만 발동.

## 인자
- `$ARGUMENTS` — 시간 윈도우 (시간 단위, 정수). 예: `6` = 최근 6시간, `24` = 최근 24시간. 인자 없으면 기본 `6`.

## 차이점 (정상 `/update` 대비)

1. **시간 윈도우 강제 확장**
   - 정상: 최근 1~2일 (CLAUDE.md "변경 감지 방법론")
   - 강제: 사용자 지정 N시간. 폐쇄 루프 방지 광역 스캔 시에도 동일 윈도우 적용.

2. **"변경 없음 → 종료" 가드 해제**
   - 정상: 신규 이벤트 없으면 커밋 없이 "변경 없음" 보고 후 종료
   - 강제: 신규 이벤트 없어도 **오늘(KST) 기존 엔트리의 prose 정합성 점검 → 정책 위반 발견 시 통합 재작성으로 갱신**
     - 점검 항목 (CLAUDE.md 기반):
       - **탭 콘텐츠 독립성 위반**: 한국 탭에 미국 기업명 직접 인용, AI 탭에 일반 빅테크 IR, 원자재 탭에 종목명 등
       - **트레이더 은어 잔존**: "비트", "미스", "인라인" → "컨센 상회/하회/부합"
       - **편집자 메타 표현**: "rs 갱신", "~반영", "맥락 갱신" 등 내부 필드명 노출
       - **친구톡 가독성**: summary 줄별 독립 사건 구조 위반(병렬 나열을 줄바꿈으로 분리한 경우 등)
   - 점검 결과 위반 0건이면 정상 `/update`와 동일하게 "변경 없음" 종료

3. **작용 범위 = 오늘(KST) 엔트리만**
   - 어제 이전 엔트리는 절대 소급 수정 금지 (CLAUDE.md 누적 원칙 그대로)
   - 통합 재작성도 동일 날짜 엔트리끼리만

4. **커밋 메시지 차별화**
   - 정상: `데이터 자동 갱신 YYYY-MM-DD`
   - 강제: `데이터 정합성 강제 갱신 YYYY-MM-DD (force, ${N}h)` — git log에서 한눈에 구분

## 파이프라인

1. **조사** — N시간 윈도우로 6개 탭 병렬 웹검색. 일본 탭은 제외(`/update`와 동일).
2. **정책 점검** — 오늘 엔트리의 `summary`·`detail`·`text` 전수 스캔, 위반 항목 표시.
3. **판단·편집**:
   - 신규 이벤트 발견 → 일반 prepend (CLAUDE.md 규칙 그대로)
   - 정책 위반만 있고 신규 이벤트 없음 → 같은 날 엔트리 통합·재작성 (CLAUDE.md "같은 날 + 동일 종목·섹터로 자연스럽게 묶이면 기존 엔트리 흡수해 단일 엔트리로 재작성 가능" 규칙 활용)
   - 신규 이벤트 + 정책 위반 둘 다 → 통합 재작성으로 한 번에 처리
4. **이력**: 통합 재작성 시 `date`는 현재 KST, `changes[].time`은 원래 이벤트 시각 보존.
5. **버전**: `data/version.js` 갱신 (정상 `/update`와 동일).
6. **커밋·푸시**: 위 차별화된 메시지로.

## 보고 포맷

3~6줄 요약. 다음 항목 명시:
- 시간 윈도우 (몇 시간 강제 적용했는지)
- 신규 이벤트 건수 / 정책 위반 수정 건수
- 변경된 탭 목록
- 커밋 해시

## 주의

- 자동화(GitHub Actions·cron·다른 슬래시 명령)에서 호출 금지. 사람이 직접 입력해야만 발동.
- 호출 직후 `git log -1` 보고 `(force,` 마커가 있는지 확인하면 정상 동작 검증 가능.
